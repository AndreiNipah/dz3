Я использую REST Countries API. Это REST-сервис, который предоставляет информацию о странах мира. Через него приложение получает список стран, выполняет поиск по названию и загружает подробную информацию по коду страны.

В текущей версии API используется авторизация через Bearer token. Поэтому для работы приложения нужен API-ключ. Он добавляется в сетевой слой через OkHttp interceptor в заголовок:

Authorization: Bearer <API_KEY>

Ключ бесплатный и неограниченный в использовании, поэтому он уже вставлен в код проекта.

Базовый URL:

https://api.restcountries.com/countries/


## Что было исправлено и добавлено

1) Добавлена реактивная работа через Flow

В проект была добавлена работа с Kotlin Flow.

Flow используется не просто для одного запроса, а для реактивного состояния экранов. Данные из поиска, фильтра, избранного, истории и деталей собираются через Flow и обновляют UI автоматически.

2) SearchViewModel переведён на StateFlow

SearchViewModel теперь хранит состояние экрана как StateFlow.

В поиске используются:
- queryFlow;
- filterFlow;
- refreshFlow;
- favouritesFlow.

Они объединяются и преобразуются в общее состояние SearchScreenState.

3) Добавлен debounce для поиска

Для строки поиска добавлен debounce.

Это нужно, чтобы приложение не делало запрос на каждую введённую букву сразу. Запрос выполняется после небольшой паузы во вводе.

Также добавлена проверка минимальной длины запроса. Если пользователь ввёл слишком мало символов, показывается Empty-состояние.

4) Добавлена фильтрация стран

На главном экране добавлены фильтры по регионам:
- All;
- Africa;
- Americas;
- Asia;
- Europe;
- Oceania.

Фильтр работает вместе с поиском. Состояние выбранного фильтра хранится во Flow и объединяется с результатами поиска.

5) Используется combine

В проекте используется combine для объединения нескольких источников данных.

Например, SearchViewModel объединяет:
- поисковый запрос;
- выбранный фильтр;
- список избранных стран;
- результат поиска.

HistoryViewModel объединяет:
- историю просмотров;
- избранные страны.

CountryDetailsViewModel объединяет:
- загруженные детали страны;
- список избранных стран.

6) Используется flatMapLatest

Для поиска и загрузки деталей используется flatMapLatest.

Это нужно, чтобы старый запрос отменялся, если пользователь быстро изменил поисковую строку или открыл другую страну.

Например, если пользователь быстро вводит новый текст в поиск, старый запрос больше не должен перезаписывать новый результат.

7) Используется SharedFlow для обновления

Для ручного обновления списка используется SharedFlow.

Кнопка Refresh отправляет событие обновления, после чего SearchViewModel заново загружает данные.

Это сделано как отдельный поток событий, а не как обычная переменная.

8) FavouritesViewModel выделен отдельно

Экран Favourites больше не использует SearchViewModel.

Для него добавлен отдельный FavouritesViewModel, который наблюдает только за избранными странами из Room.

Это исправляет проблему, когда при открытии избранного запускалась лишняя логика поиска.

9) HistoryViewModel переписан через Flow

HistoryViewModel теперь не хранит Room Entity напрямую в UI.

История просмотров преобразуется в доменную модель и объединяется со списком избранных стран через combine.

Так экран History может показывать историю и одновременно знать, какие страны уже добавлены в избранное.

10) CountryDetailsViewModel переписан через Flow

Экран деталей страны теперь использует Flow-подход.

В нём есть:
- загрузка деталей по коду страны;
- retry;
- наблюдение за избранным;
- добавление страны в историю после успешной загрузки деталей.

Состояние экрана отдаётся как StateFlow.

11) Сохранена работа Room

Room продолжает использоваться для хранения локальных пользовательских данных:
- избранных стран;
- истории просмотров.

Избранное и история сохраняются после перезапуска приложения.

12) Сохранена работа Hilt

Hilt используется для создания:
- Retrofit;
- OkHttpClient;
- RestCountriesApi;
- Room database;
- DAO;
- CountriesRepository;
- ViewModel.

13) Исправлена обработка состояний

Для экранов используются состояния:
- Loading;
- Success;
- Empty;
- Error.

Если произошла ошибка сети, пользователь может повторить запрос через Retry/Refresh.

Если поиск ничего не нашёл, приложение показывает Empty-состояние, а не падает.


## Какие источники данных используются

В проекте есть несколько источников данных и событий:

1) queryFlow

Отвечает за текст поиска.

2) filterFlow

Отвечает за выбранный регион.

3) refreshFlow

Отвечает за ручное обновление через кнопку Refresh.

4) favouritesFlow

Отвечает за список избранных стран из Room.

5) historyFlow

Отвечает за историю просмотров из Room.

6) detailsFlow

Отвечает за загрузку деталей конкретной страны.
