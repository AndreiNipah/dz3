Нетривиальные тесты

В проекте есть нетривиальные тесты, которые проверяют не только итоговое значение, но и сам контракт поведения:
- повторное добавление в избранное не создаёт дублей;
- после ошибки повторный запрос через `retry/refresh` действительно приводит к новой попытке загрузки;
- устаревший запрос не должен перезаписывать результат более нового запроса;
- для Flow проверяется полная последовательность эмиссий, а не только конечное состояние.

Покрытые сценарии

1. Юнит-тесты ViewModel

Покрыты основные сценарии работы `SearchViewModel` и `CountryDetailsViewModel`:

- успешный поиск стран;
- ошибка при поиске;
- пустой результат поиска;
- повторная загрузка после ошибки;
- успешная загрузка детальной информации по стране;
- отмена устаревшего запроса при новом поисковом вводе, чтобы старый ответ не попал в UI.

2. Юнит-тесты data-слоя и бизнес-логики

Покрыты сценарии работы `CountriesRepository`:

- добавление страны в избранное;
- повторное добавление одной и той же страны без создания дубля;
- очистка истории просмотров;
- добавление одной и той же страны в историю несколько раз;
- сортировка истории по времени просмотра по убыванию;
- корректное получение и маппинг списка стран из API;
- корректное получение и маппинг детальной информации по стране.

3. UI-тесты

Покрыты пользовательские сценарии интерфейса:

- на пустом поиске отображается сообщение `Enter a country name`;
- при ошибке отображается кнопка `Retry`;
- при клике по элементу списка открываются детали именно нужной страны.


4. Интеграционные тесты

В проекте есть интеграционные тесты двух типов:

Интеграция data-слоя

Проверяется связка **Repository + Room**:
- после добавления страны в избранное данные реально сохраняются и затем читаются через `observeFavourites()`.

Интеграция UI

Проверяются сценарии экрана поиска:
- отображение кнопки `Retry` в состоянии ошибки;
- переход в детали по клику на конкретную страну из списка.

Проверки Flow

Так как в проекте используется `Flow`, добавлены отдельные проверки потокового поведения:

Полная последовательность эмиссий

Тест `observeFavourites_emits_full_sequence` проверяет последовательность состояний:
1. начальное пустое значение;
2. появление элемента после добавления в избранное;
3. повторное пустое состояние после удаления.

Этот тест важен тем, что проверяет именно поток эмиссий, а не только финальное состояние.
